# 实现映射与分阶段落地

本文件把设计稿映射到当前代码结构，确保不是只好看、做不出来。

## 1. 当前代码入口

### Chat TUI
- 文件：`src/command/tui/chat.tui.tsx`
- 当前结构：
  - Header
  - Conversation
  - Input bar

### Ops TUI
- 文件：`src/command/tui/index.tsx`
- 当前结构：
  - Header
  - Left nav
  - Main panel

## 2. Chat TUI 建议组件拆分

建议在现有 `chat.tui.tsx` 内进一步拆成：

- `ChatHeader`
- `ChatStatusStrip`
- `ConversationPane`
- `TurnCard`
- `TurnTraceRow`
- `TurnDetailsPanel`
- `ComposerBar`
- `RightInspector`（宽屏条件渲染）

### 2.1 对现有数据结构的映射

当前已有：
- `turns`
- `phase`
- `processing`
- `expanded`
- `mcpCalls`
- `skills`
- `blackboardText`
- `reply.metadata`

足以支撑：
- trace chips
- turn summary
- details panel
- current session strip

### 2.2 需要新增的轻量状态

建议新增但不复杂：
- `selectedTurnId?: string`
- `showMetadata?: boolean`
- `compactMode: boolean`（根据 cols 推导）
- `showInspector: boolean`（根据 cols 推导）

### 2.3 宽度断点建议

- `cols >= 140`: show right inspector
- `cols >= 100`: full header + status strip
- `cols < 100`: compact header
- `cols < 80`: minimal mode

### 2.4 事件映射建议

把已有 runtime events 产品化为 trace：
- BlackboardTurnStart -> board active
- SkillContextBuilt -> skills loaded
- McpToolCallExecuted -> tool count + last tool
- AgentTurnEnd -> done

如果后续想更细，可接：
- AgentTurnStart
- Perf / route events
- sandbox approval events

## 3. Ops TUI 建议组件拆分

当前 `src/command/tui/index.tsx` 里页面逻辑比较集中。

建议拆为：
- `TuiShell`
- `TopHeader`
- `SideNav`
- `BottomHints`
- `HomeView`
- `RuntimeView`
- `ChannelsView`
- `BlackboardView`
- `ActivityView`
- `HelpView`

### 3.1 当前可直接复用的数据

已有：
- `snapshot.config`
- `snapshot.gateway`
- `snapshot.blackboardTurns`
- `loadedAt`

足以支撑 Home / Runtime / Channels / Blackboard 四页。

### 3.2 Activity 页需要补的数据

当前最可能需要新增：
- runtime event ring buffer
- gateway recent events snapshot
- recent warnings/errors collection

实现方式建议：
- 在 app composition root 挂一个内存 event sink
- 仅保留最近 100~300 条 JSON-serializable event summary
- TUI 读取它，不做复杂历史查询

### 3.3 Help 页最容易做
- 纯静态渲染即可
- 无额外数据依赖

## 4. 推荐分三阶段落地

### Phase 1：结构重构
目标：观感先升级，风险最低

内容：
- chat 增加 header/status strip/turn card 层级
- ops 重排 header/nav/content
- 统一颜色与标题系统
- 增加 help view

风险：低
收益：立竿见影

### Phase 2：信息增强
目标：让 UI 真正对调试有价值

内容：
- chat trace chips
- chat metadata 面板
- ops home summary cards
- ops channel status chips
- ops blackboard timeline 更强结构化

风险：中
收益：产品感显著增强

### Phase 3：事件流与高级交互
目标：让 TUI 成为真实控制台

内容：
- activity view
- selected item detail
- 更好的 keyboard focus 模型
- compact/minimal responsive mode
- 可能的 approval overlay

风险：中高
收益：形成完整终端工作台

## 5. 哪些设计是“今天就能做”的

可以直接开始：
- 统一 header / footer
- 统一 badge 样式
- Chat turn card 重排
- Chat status strip
- Ops Home / Runtime / Help 页面
- 渠道页 row 样式优化

## 6. 哪些设计依赖后端或数据补充

需要新增数据支持：
- Activity 页
- 更细粒度 runtime phase
- sandbox approval 交互层
- richer metadata 面板

## 7. 工程建议

### 7.1 先不要引入新 UI 库
当前只用 Ink 就够，避免加复杂依赖影响 bun compile。

### 7.2 抽颜色与符号常量
建议新增：
- `src/command/tui/theme.ts`
- `src/command/tui/layout.ts`
- `src/command/tui/icons.ts`

### 7.3 组件化但别过度
终端 UI 层次比 Web 简单，拆到“页面组件 + 公共 render helper”即可。

## 8. 结论

这套设计的关键价值不在“更炫”，而在于：
- 与 Flyflor IP 一致
- 与现有代码一致
- 与终端能力一致
- 可以分阶段落地
