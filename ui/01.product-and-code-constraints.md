# 代码能力与设计边界研究

本次设计基于当前项目真实实现，而不是空想式改版。

## 1. 当前入口与技术栈

已确认：
- 终端 UI 使用 `ink` + `react`
- 主要文件：
  - `src/command/tui/index.tsx`：运维总览型 TUI
  - `src/command/tui/chat.tui.tsx`：聊天型 TUI
- 命令入口存在：
  - `bun run app.ts tui`
  - `bun run app.ts chat`
  - `docker exec -it flyflor-dev flyflor`

`package.json` 证明当前依赖里没有复杂终端组件库，只有：
- `ink`
- `react`
- `picocolors`
- `cli-table3`

所以设计必须兼容 “纯 Ink 文本界面” 的实现模式。

## 2. 当前 chat TUI 已支持的能力

从 `src/command/tui/chat.tui.tsx` 可确认：
- 单行 header + 对话区 + 输入区三段布局
- 支持输入光标位置维护
- 支持中日韩输入法场景
- 支持上下翻阅历史
- 支持处理状态 phase：
  - idle
  - blackboard
  - thinking
  - mcp
  - skill
  - streaming
- 支持根据 runtime eventBus 订阅事件：
  - BlackboardTurnStart
  - BlackboardTurnEnd
  - McpToolCallExecuted
  - SkillContextBuilt
  - AgentTurnEnd
- 支持折叠区块：
  - blackboard
  - skills
  - mcp
- 支持 keyboard shortcuts：
  - Enter 发送
  - Ctrl+C / Esc 退出
  - Ctrl+L 清屏
  - Ctrl+B / Ctrl+T / Ctrl+S 展开折叠
  - Tab 快速切 blackboard
  - 上下翻页/分页/Home/End
- 底部输入栏固定

结论：
当前 chat TUI 的可行升级方向，不是“换技术栈”，而是：
- 强化布局分区
- 改善状态反馈
- 强化层级与扫描效率
- 把事件流显式产品化
- 给历史 turn 更好的卡片结构

## 3. 当前运维 TUI 已支持的能力

从 `src/command/tui/index.tsx` 可确认：
- 三视图结构：
  - Overview
  - Channels
  - Blackboard
- 左侧 views 导航
- 右侧主内容区
- 每秒自动 refresh
- 支持 q/Esc 退出，h/l/j/k 或方向键切视图，r 刷新
- 可展示：
  - model/provider
  - gateway running/stopped
  - channels 状态
  - 最新 blackboard turn
  - blackboard transcript / steps / decisions

结论：
当前运维 TUI 已经有“控制台”雏形，适合升级为：
- 全局状态驾驶舱
- channel 健康页
- blackboard 任务页
- event/activity 时间线页
- settings/help 页

## 4. Ink 终端 UI 的现实边界

可以稳定做：
- 多栏布局
- 固定头部/底部
- box border
- 状态色彩系统
- 列表选中态
- 键盘导航
- 分屏信息架构
- 可折叠详情区
- 伪 modal / overlay（通过条件渲染）
- loading / progress / streaming 状态
- 响应式降级（按 terminal 宽度切换单栏/双栏）

不建议强做：
- 复杂鼠标交互
- 真正自由定位像素 UI
- 过重的 emoji 动效依赖
- 大量 box drawing 字符拼超复杂装饰
- 依赖透明层、阴影、模糊等视觉效果
- 超长单屏 dashboard 塞太多面板

## 5. docker exec 场景特殊约束

`docker exec -it flyflor-dev flyflor` 常见问题：
- 终端宽度不稳定
- 字体/emoji 支持不一致
- 颜色层次可能弱于本机终端
- 鼠标事件不可依赖
- 用户可能主要依赖键盘

因此新 UI 必须：
- 在 80 列宽下仍能工作
- 颜色不是唯一信息来源，要有文本标签和图标冗余
- 快捷键必须全量可见
- 重要状态必须 plain text 可读
- 输入栏与运行状态必须始终固定可见

## 6. 设计总原则

1. 信息分层优先于装饰
2. 一屏只强调一个主任务
3. chat TUI 强调“当前轮次状态感 + 历史可回看”
4. ops TUI 强调“系统状态扫描 + 问题定位”
5. 所有高级设计都必须能映射回当前 Ink 组件树
6. 第一阶段优先做布局重构，不先追求花哨视觉
