# 关键交互流程

本文件描述用户在新 UI 里的典型操作路径。

## 1. Chat：标准提问流程

1. 用户进入 chat TUI
2. 看见空态与顶栏提示
3. 在 composer 输入消息
4. 按 Enter 发送
5. status strip 进入 thinking
6. 若 blackboard 启动，trace chip 点亮
7. 若 skill / tool 发生，对应 chip 更新数量
8. assistant 输出流式出现
9. turn 收束，状态从 running 变为 done
10. 用户可按 Tab / Ctrl+T / Ctrl+B 查看本轮详情

## 2. Chat：回看工具调用流程

1. 用户发送一个需要工具的任务
2. turn 完成后，trace summary 显示 `tool×N`
3. 用户按 `Ctrl+T`
4. 展开 Tools details
5. 查看：
   - server
   - tool
   - success/fail
   - result summary
6. 关闭详情，继续下一轮

## 3. Chat：处理出错流程

1. runtime 或 tool 发生错误
2. 当前 turn 出现 error chip
3. 顶部 status strip 显示 last error
4. 对话区 assistant 下方出现 error block
5. 若有 tool trace，则 details 中可看到失败点

## 4. Chat：历史回看流程

1. 用户滚动上翻
2. 顶栏显示 `SCROLLED` / `history +N`
3. 用户查看旧 turn
4. 按 End 或下翻回到底部
5. 恢复 `LIVE`

## 5. Ops：快速健康检查流程

1. 用户进入 `flyflor tui`
2. 默认落在 Home
3. 一眼看到：
   - gateway 是否运行
   - channels connected/degraded 数
   - latest blackboard 状态
   - recent alerts
4. 若发现 degraded > 0，切 Channels
5. 在 Channels 中查看具体哪个 channel 异常

## 6. Ops：排查 blackboard 卡住流程

1. Home 看到 latest blackboard status 不正常
2. 切到 Blackboard
3. 看 goal / status / decisions
4. 看 worker steps timeline
5. 观察 blockers
6. 判断是工具卡住、渠道问题还是推理收敛失败

## 7. Ops：查看近期异常流程

1. 切到 Activity
2. 浏览最近 N 条事件
3. 按事件类型观察：
   - WARN
   - ERROR
   - TOOL
   - BOARD
   - CHANNEL
4. 回切对应页面深入看

## 8. 帮助发现流程

1. 用户第一次进入
2. 顶栏与底栏都能看到高频快捷键
3. 不懂术语时切 Help
4. Help 页给出状态图例和术语定义

## 9. 为什么这些流程合理

因为它们都符合当前代码和终端现实：
- 主要依赖键盘
- 适合列表与卡片结构
- 能利用现有 runtime event bus
- 不要求复杂鼠标或富图形能力
