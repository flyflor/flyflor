# Ops / Overview TUI 重设计方案

## 1. 目标定位

`flyflor tui` 应从“状态页”升级成“运行控制台”。

核心任务：
- 看系统是否健康
- 看渠道是否可用
- 看 blackboard 在做什么
- 看最近发生了什么异常
- 快速定位当前问题在哪一层

## 2. 页面结构升级

从当前三页升级为六页：
- Home
- Runtime
- Channels
- Blackboard
- Activity
- Help

这六页都能用当前 Ink 模型实现。

## 3. 总体布局

建议布局：
- Top Header
- Left Nav
- Main Content
- Optional Right Rail（宽屏）
- Bottom Hint Bar

### Top Header
显示：
- flyflor banner 简化版
- provider/model
- gateway status
- connected/degraded counts
- last refresh

### Left Nav
显示页面列表与选中态。

### Main Content
根据 page 渲染卡片。

### Right Rail
宽屏时显示：
- summary
- alert list
- hotkeys
- selected item detail

### Bottom Hint Bar
显示：
- q quit
- r refresh
- h/l switch
- j/k move
- Enter expand

## 4. Home 页面

Home 页面要做到“3 秒扫描就知道系统大概情况”。

建议卡片：
1. System Health
2. Runtime Config
3. Channel Summary
4. Latest Blackboard Turn
5. Recent Alerts

### 4.1 System Health
显示：
- gateway running/stopped
- connected channels count
- degraded channels count
- memory enabled
- sandbox mode

### 4.2 Runtime Config
显示：
- provider / model
- api mode
- config path
- build target / version（若可取）

### 4.3 Channel Summary
显示每类 channel 的状态聚合，不展示全部细节。

### 4.4 Latest Blackboard Turn
显示：
- status
- goal 摘要
- latest worker step
- decisions count
- blockers count

### 4.5 Recent Alerts
显示最后几条警告或错误：
- channel degraded
- provider fallback
- tool denied
- memory failure

## 5. Runtime 页面

聚焦系统运行形态，不再混在 Home。

卡片建议：
- Identity
- Model & Provider
- Memory & Crystal
- Sandbox
- Gateway
- Processes / Events（若后续支持）

这页偏“配置 + 当前运行态”。

## 6. Channels 页面

这是最重要的运维页面之一。

建议改成两层结构：
- 上方状态统计条
- 下方 channel 列表

每个 channel row 展示：
- name
- state chip
- transport
- last activity
- detail
- last error

如果宽屏足够，可右侧显示选中 channel 的完整 detail。

### 状态语义
- connected = green
- polling/processing/replying = cyan or blue
- waiting/needs binding = yellow
- degraded/needs setup = red or amber
- unknown = gray

## 7. Blackboard 页面

当前已有 transcript + steps，但还不够像“任务板”。

建议结构：
- Header summary
- Goal
- Status chips
- Decisions
- Transcript timeline
- Worker steps timeline
- Facts / blockers

### 页面重点
不是把所有 message 平铺，而是强调：
- 目标是什么
- 现在推进到了哪一步
- 为什么卡住或收敛

## 8. Activity 页面

这是目前代码里未完全成型、但非常值得补的一页。

它展示统一事件时间线，来源可逐步接入 runtime event bus。

建议事件类型：
- gateway message received
- blackboard turn start/end
- skill context built
- tool executed
- provider fallback
- sandbox denied
- process start/exit
- channel error

### 活动列表样式
每行：
- 时间
- 类型 chip
- summary
- 关联对象

例如：
- `18:31  TOOL   mcp.fs.read ok  req:abc123`
- `18:31  BOARD  turn start      req:abc123`
- `18:32  WARN   provider fallback openai->anthropic`

这一页很适合调试系统实际行为。

## 9. Help 页面

帮助页是必须的，因为终端 UI 没有天然 discoverability。

内容：
- 全局快捷键
- 页面导航键
- 状态颜色图例
- 术语解释：
  - blackboard
  - crystal
  - tool call
  - degraded
  - sandbox denied

## 10. 窄屏降级策略

如果宽度不够：
- 去掉 right rail
- left nav 缩成更窄
- 卡片改竖排
- 某些字段只显示摘要

如果仍不足：
- nav 切成顶部 tabs
- 单页顺序流式布局

## 11. 为什么这套更可做

因为当前运维 TUI 已有：
- 视图切换
- 定时刷新
- 黑板摘要和详情
- 渠道状态

新增主要是：
- 重排信息结构
- 多几个 view
- 丰富 summary 卡片
- 增加 activity 数据源

工程难度是“中等重构”，不是从零重写。
