# Chat TUI 重设计方案

## 1. 目标

当前 chat TUI 已经具备基础可用性，但还偏“日志式聊天”。

重设计目标：
- 更像智能体工作台
- 更强的过程可见性
- 更清晰的 turn 层级
- 更稳的窄终端兼容性
- 保持 Ink 可实现

## 2. 新布局

推荐布局：

1. Top Bar
2. Session Status Strip
3. Conversation Timeline
4. Composer

在宽终端上：
- 主对话区 + 右侧 Inspector

在中窄终端上：
- Inspector 折叠成顶部 summary strip

## 3. 顶栏设计

顶栏内容：
- 左侧：Flyflor 标识 + Chat 模式 + 当前 agent 名称
- 中部：当前 session 状态 chip
- 右侧：快捷键摘要

示例：
- `FLYFLOR  Chat  agent: flyflor`
- `[IDLE]` / `[THINKING]` / `[BLACKBOARD]` / `[TOOLS]` / `[STREAMING]`
- `Enter send · ↑↓ history · Tab details · ^T tools · ^C quit`

设计目的：
- 让用户一眼知道当前在哪个模式
- 强化“不是普通 shell，而是 agent console”

## 4. Session Status Strip

这一条是 chat 重设计里的关键新增层。

它位于顶栏下方，用来展示“当前轮次的实时摘要”：
- 当前 phase
- blackboard 是否启用
- 当前 tool count
- skill count
- 错误提示

示例：
- `phase: thinking | blackboard: active | skills: 2 | tools: 1 | scroll: live`

它比把所有信息塞进 header 更清晰，也比只在回复里埋信息更可扫描。

## 5. 对话卡片结构

每个 turn 不再只是简单上下文块，而改成更强的卡片结构。

### Turn Card 结构

A. User Row
- 用户标识
- 时间
- prompt 正文

B. Runtime Summary Row
- phase trail
- tool/skill/blackboard chip
- status badge

C. Assistant Row
- agent 名
- 回复正文

D. Details Panel
- Blackboard details
- Skill list
- Tool trace
- Metadata

## 6. Turn 的视觉分层

建议层级：
- User：cyan
- Agent：green
- Runtime trace：yellow/blue/magenta 中性点缀
- Error：red
- Secondary meta：gray

不要全屏大量彩色，避免噪音。

## 7. Runtime Summary Row 设计

这是最重要的产品增强点。

将当前已有事件映射成固定顺序的 trace chips：
- route
- think
- board
- skill
- tool
- write

显示规则：
- 未发生：dim
- 进行中：高亮 + 动态点
- 已完成：solid chip
- 出错：红色 error chip

例如：
- `[think] [board] [skill×2] [tool×1] [write]`

这样比当前单独折叠卡片更适合快速扫描。

## 8. 右侧 Inspector（宽屏模式）

当终端够宽时，增加右侧轻量 inspector。

包含：
- Current turn state
- Last skill names
- Last tool calls
- Blackboard active summary
- Keyboard hints

作用：
- 不打断主对话流
- 又能把结构化信息固定呈现出来

如果终端太窄，则取消右栏，改回顶部 strip。

## 9. 输入区重设计

当前输入栏功能够用，但视觉上太轻。

建议改成：
- 左侧提示符 `›`
- 中部输入内容
- 右侧显示发送状态 / phase icon
- 底部一行次级帮助文本（窄屏可隐藏）

Idle 时：
- `Type a message…`

Processing 时：
- `Agent is thinking… Enter disabled`

如果未来支持多行输入，再升级；当前先保持单行输入最稳。

## 10. 历史滚动与回看

当前已支持 scrollOfs。

建议在 UI 上显式给出：
- 顶部显示 `history +N`
- 非 live 模式时显示 `SCROLLED` badge
- 回到底部时恢复 `LIVE`

这对调试 agent 很重要，因为用户经常会回看上轮工具调用。

## 11. 详情区折叠模型

当前只有 latest turn 通过快捷键切详情，概念是对的，但交互可更统一。

建议：
- `Tab`：切换当前焦点 turn 的主详情
- `Shift+Tab`：切换详情块焦点（如果 Ink 键支持不足，可不做）
- `Ctrl+B`：Blackboard
- `Ctrl+T`：Tools
- `Ctrl+S`：Skills
- `m`：metadata（建议新增）

详情内容顺序：
1. Blackboard
2. Skills
3. Tools
4. Metadata

## 12. 空态设计

当前空态只有两句文案。

建议优化成：
- 中央标题：`Start an agent session`
- 次级说明：
  - Ask a question
  - Request a task
  - Inspect reasoning with details
- 底部短提示：`Press Enter to send • Ctrl+C to quit`

## 13. 错误态设计

错误不应只在底部红字出现。

建议：
- 当前 turn card 内显示 error chip
- 顶部 status strip 同步显示 `last error`
- 如果是 tool/approval error，则在 details 中归档

## 14. 推荐的最终 chat 信息结构

### 标准模式
- header
- status strip
- conversation
- composer

### 宽屏增强模式
- left: conversation
- right: inspector
- bottom: composer

## 15. 重点实现收益

这套方案不要求底层大改，就能明显改善：
- 可读性
- 专业感
- 调试效率
- 智能体“过程透明”体验
