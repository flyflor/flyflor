# 信息架构总图

本提案把终端 UI 分成两条产品线，但保持统一设计语言。

## A. Chat TUI

目标：让用户在终端里“像在专业智能体工作台里聊天”，而不是只看一串纯文本。

### A1. 一级结构

1. Top Bar 顶栏
2. Conversation Pane 主对话区
3. Inspector Strip 轻量检查条
4. Composer 输入区
5. Toast / Overlay 临时提示层

### A2. 主对话区内部结构

每个 turn 由 4 层组成：

1. User Prompt
2. Agent Runtime Trace Summary
3. Assistant Response
4. Optional Details

### A3. Trace Summary 结构

建议按事件自然顺序排：
- Route / Thinking
- Blackboard
- Skills
- Tools
- Output

不是所有 turn 都全显；按真实事件出现。

### A4. Chat TUI 的信息优先级

P0：当前是否正在处理、输入框是否可用
P1：最新一轮 agent 正在做什么
P2：最终回复内容
P3：本轮用了哪些技能、工具、blackboard
P4：更老历史内容

## B. Ops TUI

目标：让用户在一个终端页里看到 flyflor 当前系统健康、渠道、blackboard、活动流。

### B1. 一级导航

建议从当前 3 个视图升级为 6 个：
- Home
- Runtime
- Channels
- Blackboard
- Activity
- Help

### B2. 各页面定义

#### Home
一屏总览：
- 当前 provider/model
- gateway 状态
- channel connected/degraded 数量
- 最近 blackboard 任务
- 最近告警

#### Runtime
运行时配置与能力：
- sandbox 模式
- memory/crystal 开关
- provider/api mode
- build/runtime version
- 当前处理态摘要

#### Channels
渠道健康矩阵：
- channel 名称
- transport
- state
- last activity
- last error
- detail

#### Blackboard
任务工作台：
- 最新 turn 状态
- goal
- decisions
- recent transcript
- worker steps
- blockers / new facts

#### Activity
统一事件时间线：
- gateway events
- runtime events
- tool calls
- blackboard transitions
- provider fallback / error

#### Help
快捷键、状态图例、术语解释。

## C. 共用设计语言

两个 TUI 共享：
- 统一 top bar 样式
- 统一 color semantics
- 统一状态芯片写法
- 统一空态、错误态、loading 态
- 统一快捷键提示样式
- 统一卡片边界与内容密度

## D. 响应式终端策略

### 宽屏 >= 140 cols
- 可双栏
- Chat 可显示右侧 inspector
- Ops 可显示 side nav + content + side summary

### 中屏 100-139 cols
- 双栏但压缩说明文字
- inspector 改成一行 summary strip

### 窄屏 80-99 cols
- 单栏
- 重要 meta 收拢到摘要行
- 卡片标题保留，详情默认折叠

### 极窄 < 80 cols
- 只保证可用，不保证完整观感
- 自动切简化模式：
  - 更短 header
  - 不显示次级说明
  - 列表改单列

## E. 信息呈现原则

1. 不让用户横向扫描太多长句
2. 优先用“标签 + 数值 + 状态词”组合
3. 长文本默认摘要，用户按键展开
4. 所有详情区都能折叠
5. 最新事件永远靠近当前焦点
