# Development Workflow

## Position

This repository is the Bun kernel workspace. Work on source, docs, templates and tests here; do not implement the Rust shell in this repository.

## Parallel Work

When the work expands into independent slices, use `git worktree + tmux + Codex` lanes. Each lane should have a narrow write scope and explicit red lines.

Current recurring lanes:

- socket/control/event/read snapshots
- computer/coding/external tool surfaces
- LSP/task/data utilities
- media/search/web sidecars
- documentation and Apifox contract seal

## Before Editing

Run:

```bash
pwd
git branch --show-current
git status --short --branch
```

Read the relevant owner docs and code. Prefer structural tools when available; otherwise use `rg --files`, `rg`, and direct file reads.

## Documentation Rules

- Active docs must have synchronized English `.md` and Chinese `.zh.cn.md` pairs.
- Do not patch stale docs into a half-correct state. Move mismatched active docs into `docs/old-docs/` with traceable names, then regenerate.
- Generated OpenAPI/Apifox artifacts are updated through their scripts.
- Prompt-template documentation in root README files is generated by `bun run docs:prompts --write`.

## Verification

Use Bun commands only:

```bash
bun run docs:check
bun run check
bun run test:kernel
bun run build:binary
```

For socket work, add the focused socket/control tests or smoke scripts relevant to the changed surface.

## Handoff

Before pausing or switching environments, update:

- `TODO.md`
- `LOGS.md`
- `docs/development.workflow.md`

Do not commit or push unless the coordinator explicitly asks for that action.
